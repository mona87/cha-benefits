#### Anti-Patterns Verdict

**Start here.** Does this look AI-generated? **No**, with one detail worth a second look.

**LLM assessment**: This actively avoids every anti-pattern named in its own PRODUCT.md — no gradient text, no decorative glassmorphism, no hero-metric tiles, no identical card grids (the benefits section is a genuine editorial list, ritual is a timeline), no modals, no urgency copy. The custom canvas particle field, the SVG cup with real color-interpolation tied to steep progress, and the italic-word rule applied to one *specific* emotionally-loaded word per headline (never generically) all read as bespoke work, not template output. `.benefit-row::before` is structurally a side-stripe accent border, gated behind hover/active rather than static — defensible per DESIGN.md's own carve-out, but a sharp-eyed reviewer would still clock the silhouette. A handful of em dashes appear in the benefits copy, used correctly for parenthetical emphasis rather than ChatGPT-style connective tissue.

**Deterministic scan** (`detect.mjs`, run against the full project directory): 3 findings, exit code 2.
- **Real, confirmed**: `layout-transition` in `css/nav.css:7` — `.nav` transitions `padding` (1.1rem → .75rem) on scroll state. This animates a layout property, which is an explicit shared-law violation and causes a real reflow on every scroll-triggered nav state change.
- **False positive**: `single-font` — the detector claims "only font used is fraunces," but the same Google Fonts `<link>` it read the finding from also loads Karla, which is used as `var(--sans)` in 30+ declarations across every CSS file (nav, buttons, kickers, form, meta text). Confirmed by direct inspection; not a real issue.
- **Low-confidence / contextual**: `overused-font` (Fraunces) — Fraunces is more common on Google Fonts now than a few years ago, but it's a documented, deliberate brand choice (DESIGN.md calls out the weight-300 + optical-sizing pairing as one of three "load-bearing decisions"), not a generic default like Inter/Roboto. Not treating this as a real issue.

**Visual overlays**: unavailable this session — no browser automation tool is loaded, so the live-server/injection step in Assessment B was skipped entirely. This critique is code-read only; two findings below are flagged as needing an actual device/browser check before acting on them.

#### Overall Impression

This is a disciplined, intentional piece of brand design — the kind of build that actually earns the "no AI slop" verdict rather than skating past it. The single biggest opportunity isn't visual: it's that the site's central promise (a functioning weekly newsletter) currently has no mechanism to be delivered, and its most novel interactive feature (the benefits row hover-swap) tells the browser it isn't interactive and is invisible on mobile. The craft is real; two structural gaps undercut what the craft is in service of.

#### What's Working

1. **The steep timer** (`js/brew.js` + the inline SVG cup) — the liquid's fill color linearly interpolates between each tea's start/end RGB across real countdown progress, so the cup visibly darkens in sync with elapsed time. Functional (teaches real brew parameters) and delightful without breaking the "drift, never bounce" motion doctrine.
2. **Faithful, disciplined execution of DESIGN.md** — the italic-word rule lands on exactly one emotionally-loaded word per headline every time ("Live greener," "quietly does," "Steeped, never rushed"), and the light/dark accent split is honored almost everywhere. A real design system in active use, not a one-off skin.
3. **Copy voice discipline** — zero exclamation points, zero unsupported superlatives, across the entire page, including at the UI-state level ("Steeping…", "Welcome. The first letter is already steeping.").

#### Priority Issues

**[P0] The newsletter signup does not create a subscriber**
- **Why it matters**: `api/subscribe.js` and `server.js` only call Resend's one-time transactional send endpoint (`POST /emails`) to fire a single "Welcome to Cha" message. There is no call to any Audiences/Contacts API and no database/list persistence anywhere in the codebase. The UI promises "Free forever · one email a week" and "the first letter is already steeping" — but nothing in this build can ever send letter two. Per PRODUCT.md, signups are the site's entire stated success metric.
- **Fix**: Call Resend's Audiences API (`resend.contacts.create`) against a real Audience ID, or persist emails to a list/DB that a separate weekly-send process reads from. Stop conflating "sent a welcome email" with "subscribed."
- **Suggested command**: `/impeccable harden`

**[P1] Gold-on-paper text fails contrast, and breaks the project's own documented rule**
- **Why it matters**: `.benefit-tag` ("Best studied") sets `color: var(--gold)` at `.58rem` on the warm-paper background. Measured: **2.24:1 contrast against `--canvas`, 2.48:1 against `--canvas-card`** — both well under the 4.5:1 AA threshold for small text (this text has no claim to the 3:1 large-text exception either). This also directly contradicts DESIGN.md's own Steeped Gold description: gold "Never appears on light sections."
- **Fix**: Give `.benefit-tag` an ink-green treatment (matching the light-section accent role) instead of gold, or darken the gold specifically for this context until it clears 4.5:1.
- **Suggested command**: `/impeccable audit`

**[P1] The site's most novel interaction is undiscoverable, and absent entirely on mobile**
- **Why it matters**: `.benefit-row { cursor: default; }` explicitly tells the browser the row isn't interactive, yet hovering it is the only way to trigger the sticky photo-swap and accent-rail reveal. First-time visitors have no cue to hover a list row — the "editorial index" mechanic likely goes unseen by most desktop visitors. On mobile, `.benefits-figure { display: none }` below 880px removes the panel entirely, so mobile visitors (who PRODUCT.md says arrive from search/social) see none of the 8 benefit photos.
- **Fix**: Remove `cursor: default`, add a visible resting-state cue (subtle rail always partially visible, or a "01/08" progress indicator), and give mobile a lightweight non-hover alternative (swipeable strip, or auto-advancing on scroll) instead of just hiding the panel.
- **Suggested command**: `/impeccable adapt`

**[P2] Nav padding transition animates a layout property (detector-confirmed)**
- **Why it matters**: `.nav` transitions `padding` between 1.1rem and .75rem on scroll state — an explicit shared-law violation ("Don't animate CSS layout properties") that forces a reflow on every scroll-triggered nav-state toggle, the opposite of the site's own "drift, never bounce, nothing janky" motion doctrine.
- **Fix**: Replace the padding transition with a `transform: scale()` or a fixed-height nav with internal content that shifts via `transform`/opacity instead.
- **Suggested command**: `/impeccable optimize`

**[P2] "Evidence-led" copy has no actual evidence attached**
- **Why it matters**: Copy repeatedly claims things like "the strongest signal in the research" and "in the largest population studies" with zero footnote or link anywhere on the page, and terms like L-theanine, EGCG, catechins, and polyphenols are never defined. DESIGN.md's own stated principle is "Evidence over hype" — right now it's evidence-*flavored* copy, not inspectable evidence, which undercuts the brand's central differentiator against wellness-industry hype (its own named anti-reference).
- **Fix**: Link each claim to (or reveal on hover/footnote) its source, and add lightweight inline glosses for the jargon terms.
- **Suggested command**: `/impeccable clarify`

**Needs a device check, not confirmed**: Assessment A flagged that `.nav-links.open` (mobile menu, `z-index: -1`) might paint behind `.nav.scrolled`'s own frosted background, making the takeover panel invisible when opened after scrolling. Working through CSS stacking-context painting order by hand suggests the opposite — the negative-z-index panel should paint above the parent's own background but below `.nav-inner`'s unpositioned content (logo/hamburger), which is actually the intended effect. Neither assessment had browser access this session to confirm either way; treat this as unverified until someone opens it on a real phone after scrolling.

#### Persona Red Flags

**Jordan (First-Timer)**: The brew section is a genuine strength — it explains *why* water is cooled and *why* less leaf means a shorter steep. But the benefits section drops unglossed science jargon with no tooltip or glossary, and nothing explains *why* Gyokuro wants 60°C while Hojicha wants 90°C beyond stating the numbers. Jordan gets the "what," not the "why," outside the brew module.

**Riley (Stress Tester)**: Riley subscribes, gets the welcome email, and waits a week for "one letter a week." Nothing arrives, ever — because nothing in the backend can send it (see P0). This is exactly the kind of gap a methodical user who tests whether a promise actually holds would find, and it directly contradicts the site's own signup-note copy ("Free forever · one email a week").

**Casey (Distracted Mobile User)**: 13 lazy-loaded images with format fallback but no width-based `srcset`/`sizes` — full-resolution assets regardless of viewport. The hero canvas runs up to 850 particles on a continuous `requestAnimationFrame` loop and the grain overlay animates on an infinite cycle, neither paused via IntersectionObserver once scrolled past — ongoing CPU/battery cost on a page whose whole brand promise is "unhurried." Combined with the benefits panel being fully hidden below 880px, mobile is where this build's edges show most.

#### Minor Observations

- `#form-error` combines `role="alert"` (implicit `aria-live="assertive"`) with an explicit `aria-live="polite"` on the same element — a contradictory pairing that likely defeats the alert role's urgency. Pick one.
- `:focus-visible` outline uses the ink-green accent globally, including inside dark pine sections where the design system's own split reserves gold for dark backgrounds — probably fine on contrast, but a brand-consistency slip worth a glance.
- No privacy-policy or data-handling link anywhere near the email capture field, despite it being the site's one conversion point.
- `min-height: 44px` is correctly applied to `.tea-pick` and `.nav-cta` — deliberate touch-target compliance, worth calling out as done right.
- The roman-numeral step labels (`i.`, `ii.`, `iii.`) in the brew section are a nice typographic touch but marginally slower to scan than arabic numerals — pure polish-level nitpick.

#### Questions to Consider

- What if the benefits panel auto-advanced on scroll position (not just hover), guaranteeing the "editorial index" mechanic is seen by every visitor, mobile included, instead of hiding behind an undiscoverable, desktop-only hover state?
- What if every evidentiary claim actually linked to its source study, turning "sourced-feeling" copy into genuinely inspectable evidence — the single biggest lever this brand has against the "wellness-industry hype" it explicitly positions itself against?
- What would it take to make "one email a week" true before anything else on this list gets touched?
